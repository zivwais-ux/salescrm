## מה זה

אפליקציית ווב בעברית (RTL) לניהול תיק לקוחות של מנהל מכירות, שנבנתה מחמישה
דוחות PDF של ה-ERP (2022–2026). **בלי שרת, בלי build, בלי תלויות בזמן טעינה** — HTML, CSS
ו-JavaScript בלבד. הנתונים חיים ב-localStorage ונטענים בפעם הראשונה מקובץ
זינוך שנבנה מה-PDF.

```
web/
  index.html        המעטפת
  css/app.css       מערכת העיצוב (אסימוני oklch, יום/לילה)
  js/config.js      שם, סניף, מפתחות אחסון
  js/format.js      פורמט מספרים ותאריכים
  js/ui.js          אייקוני SVG ורכיבים חוזרים
  js/store.js       שכבת הנתונים + היסטוריית ביטול
  js/metrics.js     חישובי הניתוח + catalog() לסיווג
  js/charts.js      גרפי SVG ללא ספריות
  js/assistant.js   מנוע השאילתות של הצ'אט
  js/excel.js       ייצוא/ייבוא
  js/importer.js    קריאת קובץ/הדבקה → תוכנית
  js/views/         dashboard, trend, customers, entry, grid, activity, settings
  js/app.js         ניווט, נושא, מגירה, צ'אט, חיפוש מהיר
  data/dataset.js   נתוני הזינוך — נוצר אוטומטית, לא לערוך ביד
tools/
  parse_pdf.py      פענוח ה-PDF ממיקומי התווים
  build_dataset.py  בונה את dataset.js / dataset.json
  read_table.py     קורא ייצוא xlsx/csv של חודש
```

עדכון מדוח חדש: `python3 tools/build_dataset.py <תיקיית ה-PDF>` (דורש `pymupdf`).
אפשר להעביר באותה שורה גם ייצוא חודשי (`xlsx`/`csv`); `tools/read_table.py`
קורא אותו (zip + XML ישירות — `openpyxl` נופל על הסגנונות של הקובץ הזה),
ו-`apply_tables` מחליף כל חודש שהוא מכסה. **סדר קריטי**: `apply_tables` רץ
*אחרי* מיזוג השנים הישנות מ-`dataset.json`, אחרת החודש שהוחלף נדרס בחזרה.
השנה נקראת משורת התקופה של הדוח, ושנה שכבר במאגר ואין לה PDF נשמרת — אפשר
להריץ על דוח בודד. **אחרי בנייה מחדש יש להעלות את `SEED_VERSION`** ב-
`build_dataset.py`, אחרת מכשיר שכבר מחזיק נתונים לא יקלוט את השינוי.

## עובדות על הנתונים — לא לשנות בלי לבדוק מחדש

הפענוח הוצלב מול הדוח עצמו, ואלה המספרים הקובעים:

- **2022: 15,483,017.74 · 2023: 18,441,363.69 · 2024: 16,183,215.31 ·
  2025: 16,203,057.74 · 2026 (ינואר–ספטמבר): 11,228,824.09 ₪**
- כל 57 סכומי החודשים תואמים לאגורה, וכן כל סיכומי הסוכנים שהדוחות מדפיסים:
  14 סיכומים ב-2022–2024, וארבעת הסיכומים של 2025 שנבדקו כשהדוח שלה נקרא
  (בני ויסמן 10,731,247.72 / אייל בן אבי 5,376,062.89 / שוקי צוקרון
  38,312.23 / דני חיים 57,434.90).
- **התיק עבר ידיים לאורך השנים** — ב-2022 שוקי צוקרון החזיק 10.4 מיליון ובני
  ויסמן 5.0; ב-2026 בני מחזיק 7.3 ושוקי אפס. זה נתון אמיתי בדוח, לא באג.
- שורת "סה"כ כללי" של הדוח נשמרת בתוך `dataset.js` תחת `control`, ומסך
  "נתונים וקבצים" מצליב מולה חודש-חודש. **אם מסך ההצלבה מפסיק להראות
  "תואם לאגורה" — משהו נשבר.** זו בדיקת האמת המהירה ביותר.

### חמישה דברים שהדוח לא אומר במפורש
1. **`20289001` "לקוחות שונים" הוא סל מרוכז, לא חברה.** המחזור שלו נספר
   בסיכומים אבל הוא מוחרג מדירוגים ומרשימות הפעולה.
2. **מספר לקוח שהוא קידומת מדויקת של אחר** — שמונה זוגות. זה **לא** באג
   פענוח: כל מספר חריג (גם בן 8 ספרות וגם עם סיומת `-1`) נבדק מול מיקומי
   התווים ב-PDF ומודפס שם בדיוק כך. מה שהקשר *אומר* אינו כתוב בדוח: בארבעה
   זוגות שני השמות זהים (אותה חברה, שני מספרי חשבון) ובשאר שונים (קרגל משמר
   השרון / משמר דוד). לכן הכרטיס מציג את העובדה בלבד ואינו מכריע.
3. **גופים שמופיעים רק כמשלמים** ולא כיעד משלוח; הם אינם לקוחות בתיק.
4. **שבע שורות תומחרו ביורו** (כ-0.6% מהמחזור). הדוח מחבר אותן לסיכומים שלו
   כמו שהן, וכך גם המערכת — אחרת ההצלבה היתה מראה פער קבוע. **המטבע הוא חלק
   ממפתח התנועה**: בלעדיו שורת יורו ושורת שקל של אותו לקוח באותו חודש דורסות
   זו את זו, ושתי שנים מפסיקות להתאים לדוח. מוצג במסך "נתונים וקבצים".
5. **ספטמבר 2026 הוא חודש חלקי** — הדוח הופק ב-17/09. הסכום נכון ונשאר,
   אבל `Metrics.partialMonth()` מזהה חודש כזה (פחות ממחצית החציון של ששת
   החודשים שלפניו), ו**כל השוואה במערכת רצה על חודשים מלאים בלבד**
   (`view.cmpMonths` / `view.cmpLabel`): המספר הגדול בלוח הבקרה הוא
   `totalSold` (ינואר–ספטמבר), וההשוואה, אחוזי השינוי, "דורש טיפול", "מי
   הזיז את המחזור" והתחזית — כולם ינואר–אוגוסט מול ינואר–אוגוסט. בלי זה:
   ‎−6.5% במקום ‎−0.1%, תחזית 14.97 מיליון במקום 16.26, ושישה לקוחות ברשימת
   "דורש טיפול" רק בגלל לוח השנה.

6. **לשנה הראשונה במאגר אין שנה קודמת.** `view.hasPrior` מבדיל בין "לא קנו
   אשתקד" לבין "אין נתוני אשתקד": בלעדיו כל לקוח ב-2022 נצבע כחדש וכל המחזור
   כצמיחה.

הסיווגים מרוכזים ב-`Metrics.catalog()`.

## חמש השנים — מה נוסף

- **מסך "מגמה"** (`views/trend.js`): סך שנתי, שנים-עשר חודשים מתגלגלים, מפת
  חום של חודש מול שנה, תמהיל סוכנים לאורך השנים, ומי צמח/נשחק מאז 2022.
- **בורר שנה** בסרגל הקשר (`#ctxbar` ב-`app.js`), ופס שנים בלוח הבקרה.
- **מפת החום** משתמשת בסולם `--heat-0..5` שנבדק לניגודיות: דיו כהה עד מדרגה
  3, לבן מעליה, וכל צירוף עומד על 4.5:1 ומעלה. **שינוי הצבעים מחייב בדיקה
  מחדש** — הסולם נמתח בין החודש הנמוך לגבוה ולא מאפס.
- **מסך המשימות** נבנה מחדש סביב ערימות דחיפות + רישום בשורה אחת (ובטלפון
  כפתור צף שפותח גיליון).
- **טבלת החודשים בטלפון** היא רשימת לקוחות; נגיעה פותחת גיליון של 12 שדות.
- **מיזוג זרע**: `Store.mergeSeed()` מחליף רק שורות `source: "erp"` ומשאיר
  עריכות, יעדים, פרופילים, שמות ששונו ידנית (`party.renamed`) ופעילות.

## הזנה ידנית — מה שחשוב לדעת

- `views/entry.js` הוא מסך ההזנה, וברירת המחדל שלו היא מצב **מקובץ**: גרירה,
  בחירת קובץ, או הדבקה בכל מקום במסך. שאר המצבים הם הקלדה: חודש נבחר, רשימת
  לקוחות עם הקשר (אותו חודש אשתקד, חודש קודם), ושדה שמקבל גם חשבון
  (`Fmt.parseAmount`).
- `js/importer.js` קורא ואינו שומר: `fromFile`/`fromText` מחזירים **תוכנית**
  (`months`, `parties`, `agents`, `problems`), והשמירה היא `Store.applyImport`
  בצעד נפרד שהמשתמש מאשר. `cellsFromXlsx` פורס את ה-zip בדפדפן
  (`DecompressionStream("deflate-raw")`) וקורא את ה-XML ישירות — שים לב
  שחלק מהייצואים כותבים אותו עם קידומת מרחב שמות (`<x:row>`), ולכן היא מוסרת
  לפני הפענוח. ספריית `xlsx` מה-CDN היא נפילה לאחור בלבד.
- `Store.applyImport({parties, agents, months}, label)` **מוחק כל חודש שהקובץ
  מכסה** ואז מכניס את שורותיו, בפעולת ביטול אחת. אל תשנה את זה למיזוג: ייצוא
  חוזר של חודש הוא התמונה המלאה שלו. שורה באפס נשמרת, שורה בלי לקוח לא.
  שקל נשמר כמטבע ריק (`Importer.currencyOf`), אחרת המפתח שונה מזה שבזרע
  ואותה מכירה נספרת פעמיים.
- `Store.setMonth(year, month, rows)` שומר חודש שלם בפעולת ביטול אחת,
  `Store.setCustomerYear(no, year, months)` שנה שלמה של לקוח, ו-`Store.setTargets`
  יעדים של שנה. שלושתם commit אחד — לא אחד לכל שורה.
- `Store.lastKnown(no)` מחזיר את המשלם והסוכן מהתנועה האחרונה של הלקוח —
  **חובה להשתמש בו בהזנה**, אחרת אותו לקוח מתפצל לשתי שורות שלא מצטברות.
- `Store.closedMonth(year)` הוא `max(מה שהדוח סגר, החודש האחרון שהוזן)` —
  זה מה שמרחיב את התקופה בכל המסכים אחרי הזנה.
- הטיוטה נשמרת ב-localStorage תחת `beny_entry_draft_v1`, בנפרד מהנתונים,
  ונמחקת בשמירה.
- עריכות שאינן מספרים יושבות גם הן ב-Store וב-undo: `setSettings` (שם ותיאור),
  `addAgent/renameAgent/removeAgent` (מחיקה מעבירה תיק לסוכן אחר),
  `changePartyNumber`, `mergeParty` (מצטבר, ולכן סך המחזור לא משתנה — נבדק),
  ו-`deletePeriod`.
- מסך "נתונים וקבצים" מפריד בין **הפרש מהדוח** (שורה שהשתנתה בחודש שיש לו
  שורת בקרה) לבין **תוספת** (חודש שאינו בדוח כלל). אל תערבב ביניהם — זו
  בדיקת האמת של המערכת.

## הצ'אט — העיקרון שאסור לשבור

`assistant.js` הוא **מנוע שאילתות דטרמיניסטי, לא מודל שפה, ובלי גישה לרשת.**
כל מספר בתשובה נשלף מ-`Metrics`/`Store`. המשמעות: הוא לא יכול להמציא נתון,
וכשאין כיסוי לשאלה הוא אומר "לא הצלחתי לפענח" ומציע שאלות שיש להן תשובה.

**אם מחליפים אותו במודל שפה — צריך אישור מפורש של המשתמש.** הוא ביקש
במפורש שלא יהיו נתונים סינתטיים.

זיהוי שם לקוח מתעלם ממילים גנריות (`GENERIC` ב-`assistant.js`), אחרת
"מי הלקוחות הגדולים?" נתפס כשאלה על החברה ששמה "לקוחות שונים". כוונות רשימה
נבדקות **לפני** זיהוי שם לקוח — הסדר ב-`RULES` משמעותי.

## עיצוב

- **אסימונים:** צבע (`--bg/--surface/--text/--accent/...`), מרווחים
  (`--sp-1..9`, בסיס 4), טיפוגרפיה (`--fs-micro..--fs-display`, שבע מדרגות),
  עומק (`--shadow-sm/--shadow/--shadow-lg`) ותנועה (`--dur-fast/--dur/--dur-slow`).
  **אין מספרים חופשיים ברכיב חדש** — אם חסרה מדרגה, מוסיפים אותה לסולם.
- **משטח הכרטיס** דרך שלושה אסימונים: `--card-bd`, `--card-ring`, `--card-el`.
  ביום אין מסגרת (צל + טבעת שיער), בלילה אין צל (מסגרת). אל תחזיר `border`
  קשיח ל-`.card` — זה שובר את אחד משני המצבים.
- **גודל טקסט:** `--fs-scale` (1 / 1.125 / 1.25) לפי `data-text` על ה-HTML.
  **כל** גודל ב-CSS כתוב כ-`calc(Npx * var(--fs-scale))` — גודל חדש חייב
  להיכתב כך, אחרת הוא לא יגדל עם השאר. ב-SVG אין ירושה, ולכן טקסט בגרפים
  עובר דרך `Charts.fs(size)`.
- **טיפוגרפיה:** Heebo. **צבע:** oklch, מותג אחד + שני צבעים סמנטיים.
- **נושא:** העדפה `auto|light|dark` ב-localStorage; רק התוצאה נחתמת כ-`data-theme`
  על ה-HTML. נקודת אמת אחת לצבעים.
- **גרפים** לפי מתודולוגיית `dataviz`: השוואה לאשתקד = הדגשה (צבע מול אפור),
  שינוי = קוטביות, פילוח סוכנים = זהות (שלושה גוונים **מאומתים** —
  `node scripts/validate_palette.js "#3987e5,#d95926,#199e70" --mode dark --surface "#12151b" --pairs all`).
  לכל גרף יש תצוגת טבלה. שינוי צבעים מחייב הרצה מחדש של המאמת.
- **נייד:** מתחת ל-1000px סרגל תחתון, טבלאות כ-כרטיסים (`cards-on-mobile`),
  גיליונות מסך מלא, שטחי נגיעה 55px, קלט 16px.

## ציור המסך — מה שאסור להחזיר אחורה

- **המעטפת נבנית פעם אחת.** `buildSidebar/buildHeader/buildTabbar` רצים
  בטעינה, המאזינים יושבים על המכל (האצלה), ואחריהם רק `syncSidebar/syncHeader/
  syncCtxbar/syncTabbar` מעדכנים מחלקות וטקסט. `app.js:render()` הוא
  התזמורת. **לא להחזיר `innerHTML` למעטפת** — זה בדיוק מה שגרם להבהוב,
  לאובדן פוקוס ולקפיצת גלילה.
- `render({ transition, scroll, keepScroll })` — `transition` לניווט בלבד,
  `keepScroll` לכל שינוי נתונים/שנה/סוכן. `Store.onChange` קשור עם
  `keepScroll: true`.
- **מיקום גלילה** נשמר לכל מסך ב-`scrollAt` ומשוחזר בחזרה אליו.
- **חיפוש וסינון מציירים גוף רשימה בלבד.** ב-`customers.js` יש `bodyRows()`
  ו-`repaint({reset})`; מאזין הקליקים יושב על ה-`tbody` ולא על השורות. אם
  מחזירים `render(root, ctx)` לתוך מאזין הקלדה — חוזרים לבעיה המקורית.
- **רשימות ארוכות במנות**: `ui.limit` + `PAGE()`; סינון מאפס למנה הראשונה.

## אוצר המילים של הרכיבים

`ui.js`: `icon` · `avatar` · `initials` · `tint` · `delta` · `empty` · `card` ·
`row` · `viewToggle` · `skeleton` · `on`.
שורת רשימה חדשה במסך כלשהו צריכה לעבור דרך `UI.row`, אחרת היא תסטה מהשאר.

## איך בודקים

```bash
cd web && python3 -m http.server 8765
```

סקריפטי הבדיקה נכתבים בסקראצ'פאד ומריצים כרומיום דרך `playwright-core`
(`npm i playwright-core`, כרומיום ב-`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`):

```bash
node baseline.js <out> [--cmp <בסיס>]   # צילומים + גובה כל מסך + גלישה + סיכומי בקרה
node feel.js            # המעטפת שורדת ניווט, פוקוס/סמן בהקלדה, זיכרון גלילה
node contrast.js        # ניגודיות לכל זוג טקסט/רקע בשני הנושאים (AA)
node a11y.js            # שמות נגישים לכפתורים ולשדות, מיקוד נראה
node paging.js          # מנות ברשימת הלקוחות + איפוס בסינון
node textsize.js        # שלושת גדלי הטקסט × 7 מסכים × 320/390/1440
node verify.js          # הצלבה מול הדוח בכל שנה + תשובות העוזר
node func.js            # בורר שנה, מגירה, צ'אט, עריכה, ביטול, רענון
node migrate.js         # מיזוג זרע חדש על נתונים שמורים מגרסה קודמת
node cmp_imp.js         # ייבוא ספטמבר מייצר בדיוק את שורות הזרע
```

`baseline.js` הוא גם **מדד יעד**: גובה העמוד לכל מסך הוא מספר שמשתפרים בו,
לא תופעת לוואי. השוואה מול בסיס שמור מדפיסה את ההפרש לכל מסך.

**בדיקת האמת המהירה**: `verify.js` חייב להחזיר `drift: 0` בכל חמש השנים.

**מגבלות הסביבה:** Google Fonts ו-cdnjs חסומים — בצילומי מסך מהסביבה יופיע
גופן ברירת מחדל, ומסלול ה-xlsx נופל לגיבוי Excel XML. אצל המשתמש שניהם עובדים.
`vercel.app` חסום מהסביבה; לאימות הפריסה משתמשים בכלי ה-Vercel MCP
(`web_fetch_vercel_url`), לא ב-curl.
